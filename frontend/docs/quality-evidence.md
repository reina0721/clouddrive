# 前端质量与验证证据

验证策略统一见[开发验证](../../docs/development/validation.md)。普通页面按所属工作区与使用方验证；共享能力、契约、依赖和配置变化扩大范围。完整 `pnpm check` 保留治理、类型、单元、构建、产物预算、浏览器、格式和文档检查。

## 证据范围

- Foundation/Architecture/Dependency 与 Codegen freshness 证明机器可检查的结构及生成一致性。
- 类型与单元测试证明所选范围；不能替代真实浏览器、文件、权限与后端验收。
- Playwright 的 mock、拦截式 backend-contract、真实文件预览分别报告，不混称真实后端全量通过。
- 视觉基线仍须人工审阅，保持原有阈值；真实设备、外部服务和未执行平台独立列明。

## 浏览器服务隔离

默认 Playwright 配置分别构建并启动两个 Next standalone 生产服务：`WEB_PORT` 为演示模式，相邻端口为拦截式 backend-contract 模式。两者显式传入认证模式、监听地址与端口，独立目录位于 `.next/playwright-<端口>/mock-production` 或 `backend-production`，包含各自的公共和静态资产。验收使用编译后的运行时，避免把按路由冷编译和 HMR 等待混入页面行为；断言超时与截图阈值不变。启动预算包含生产构建时间，测试仍不复用已经运行的服务器：HTTP 就绪不证明认证模式正确；端口被占用时直接失败，保留原服务。

开发专用检查器由 `development-contract` 项目运行，匹配 `*-dev.spec.ts`，使用第三个连续端口与独立的 `inspector-development` 目录。该服务沿用正式开发入口；生产项目明确排除开发专用用例，仍验证生产界面不提供检查器。所有用例分别归属生产、后端契约或开发契约，保留检查器交互覆盖，不通过跳过测试迁移运行模式。

测试服务显式设置 `CLOUDDRIVE_BROWSER_TEST=1`；普通开发仍使用原来的开发入口与指示器。构建或运行错误正常失败，不能回退到开发实例或复用旧产物。新增平台视觉基线须逐张查看真实截图，检查布局、文案、焦点与主题后，再以不更新截图的普通运行确认可重复；不能整套自动接受或调高差异阈值。

日常开发仍在使用默认端口时，可在另一组三个连续空闲端口运行，例如 `WEB_PORT=4273 pnpm test:browser`（PowerShell 先设置 `$env:WEB_PORT=4273`）。不要通过复用开发实例来绕过端口冲突。真实 Go 文件验收继续使用独立的 `playwright.files.config.ts` 与预览凭据，不能用本配置的演示或拦截结果替代。

## 输出和追溯

截图通过 `testInfo.outputPath()` 写入每用例产物目录，trace 与测试输出位于忽略的 test-results/playwright-report，调度耗时报告位于根 `.data/validation/`。不把结果写入文档任务目录，不凭旧成功自动跳过新检查。

交付记录实际命令、revision、环境、覆盖范围、退出码与限制。同一相关输入和环境未变且无覆盖缺口时复用结果，提交前不重复全量。历史验收材料通过 Git 查阅；本页不维护会随功能变化失效的通过数量或预算快照。
