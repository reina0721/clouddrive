# Agent 日常开发流程

本页规定日常协作流程。工程边界仍以根 README、项目范围、主题架构与实际代码为准。

## 普通任务

1. 检查 Git 状态，保护已有修改；只读取理解本次目标所需的入口、实现和调用方。
2. 在聊天中简述目标、范围、验收和必要风险，执行用户已授权的可逆工作。
3. 实施并同步受影响的当前使用说明，按[验证策略](validation.md)验证。
4. 审阅 Diff；满足验收后结束，不因提交或最后补充文字重复已经适用的检查。

普通功能、缺陷和文案调整不要求创建研究、需求、设计、任务目录或影响声明文件，不以任务 ID 作为修改前提。研究围绕缺少的事实展开；已有结论未命中刷新条件时直接复用，不因阶段或上下文切换重复全仓研究。

## 需要详细设计的变化

公共接口、模块边界、重要依赖、并发与资源模型、权限安全或数据迁移需要与风险相称的设计和验证。难以逆转的架构决定用单篇 [ADR](../architecture/adr/README.md)记录原因、后果和退出条件，不生成整套任务档案。

不可逆、删除用户数据、改变既有决定或超出已授权范围的动作，先说明具体影响并取得必要确认。用户确认后的普通实现细节不重复确认；新事实实质推翻已确认方案时才更新设计和授权边界。

## 工程底线

- 依赖显式、方向清晰，禁止循环、跨模块内部穿透和隐藏全局状态。成熟工具优先，第三方跨稳定边界时使用窄契约。
- 错误完整处理或保留原因上返；取消、超时、主要错误与清理错误不丢失。日志只在决定处理策略的边界记录，遵守[日志规范](logging.md)。
- 资源、goroutine 和子进程有明确所有者、取消和等待退出；配置与语义常量有归属。
- 注释和交付以中文为主，准确描述原因和限制；不以 TODO、假数据或隐藏回退冒充实现。
- 替换方案同次迁移调用方并删除废弃入口；不保留永久双轨。数据库历史与用户数据不因代码清理而删除。

## 服务与交付

普通 React 页面由现有热更新生效；后端二进制、启动配置、PDF frame 等确需重建时，只重启受影响的开发服务。不要每次功能都重建所有预览。已启动供用户检查的服务保持运行，报告真实地址和状态；重启失败如实说明。

验证通过后记录范围、环境、结果和未执行项。相同相关输入未变化且覆盖充分时复用证据。按本地提交 skill 精确暂存本任务文件，排除用户已有修改、凭据、数据和报告；没有用户另行要求时创建 Conventional Commit。Git 保存历史，不在工作树保存任务目录副本。
