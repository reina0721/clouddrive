# ADR141-001：URL写锁进入文件事务

状态：已确认并实施中，验证状态见任务清单。依据R141-001和当前goal直接实施授权。

保留emersion处理普通DAV及Storage同步读取租约。新增独占锁作为files所有的业务事实，固定在账号规范URL；在统一保存及传输准入、发布事务检查。协议仅扩展LOCK、UNLOCK、有界If和两个锁属性，使用标准库XML/URI，不引入协议fork、全局锁系统或第二套文件实现。

拒绝直接使用内存锁和未合并上游补丁：前者重启丢失且不能约束网页与分享，后者没有稳定生命周期契约。拒绝为锁全量更换x/net FileSystem：同步租约和原子COPY无法通过当前公开文件句柄接口直接表达，适配会引入内容缓存和跨步骤提交。go-filesystems当前要求更高Go版本，不能作为工具链内的成熟替代。

URL固定意味着MOVE不携带源锁，COPY不复制锁；目标锁及父目录成员保护在前后命名空间共同生效。以可见树的迭代DFS区间判断祖先，避免深目录把每个锁检查放大为重复父链遍历。公开令牌只表达状态，实际授权仍绑定连接ID和版本；本人解除使用IAM和记录CAS。

代价是维护窄If/XML胶水。其维护责任归files；验证必须包含实际HTTP、重启、并发发布、恶意XML与跨入口失败。XML名称使用显式前缀，保留原有namespace绑定和混合内容，避免默认namespace变化影响客户端owner里的QName；不复制上游私有解析器。

上游提供能注入同一事务锁、同步内容租约及自定义属性的稳定契约时，按刷新触发器定向评估替换；通过同一验收后一次迁移删除本地胶水，不保留双实现。没有授权实现共享锁、Office服务或跨账号解锁。
