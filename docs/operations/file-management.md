# 私有文件管理

浏览器默认进入 `/home`，管理工作区位于 `/workspace`。文件属于当前 IAM 账号；管理员账号也只能通过文件 API 操作自己的内容，不能凭其他账号文件 ID 越权读取。普通账号需要被分配 `files:read` / `files:write` 权限。公开注册沿用已有注册策略，不自动扩大默认角色权限。

## 当前能力

当前支持目录和面包屑、创建目录、单文件及多文件上传队列、拖拽、取消等待或传输、失败重试、下载、重命名、移动、多选移动/移入回收站、回收站恢复、文件名搜索、图片/视频/音乐/文档分类、排序、网格/列表、属性、占用统计及有界纯文本预览。HTML 和脚本始终按文字显示。

文件内容与元数据持久化；刷新、重新登录或正常服务重启后仍可访问。目录进入回收站后，子项不能通过搜索、文件 ID 或下载链接绕过祖先状态。回收站继续占空间；本批没有永久删除或自动清空。

公开分享、与我共享、连接挂载、离线下载、完整后台任务中心、版本管理、目录上传、剪贴板上传、分片续传、画廊缩略图、媒体播放器及 Office 协作尚未接入，不能将本批称为 Cloudreve 全量兼容。

## 配置和传输限制

模块配置 `files.maxFileBytes` 默认 32 MiB、`files.quotaBytes` 默认每账号 1 GiB、`files.concurrentUploads` 默认 2。可配置为更小的正数预算；文件上限不能超过 32 MiB，并发不能超过 2，配额不能小于单文件上限。修改 files 配置需要重启。并发名额属于当前 Application Generation；切换其他配置排空旧代期间可能同时存在两代有界请求。

Storage 的现有接口采用完整 bytes，不提供大文件流式/分片能力。Huma 在读取上传 body 前取得名额并限制字节数，空文件允许上传；内容端点不提供无鉴权的对象 URL。HTTP 总 body 限制和反向代理必须覆盖配置上限，Next 代理目前限制为 32 MiB，其他 JSON operation 仍执行各自的协议限制。纯文本预览上限 1 MiB，超限、二进制及无法解码的文本提示下载。

上传先写不可变随机对象，再在数据库事务中复核配额、名称、目标与幂等键，成功提交才可见；并发超配额的候选对象会补偿清理。数据库与对象存储没有跨资源事务，进程被强制终止时可能留下未引用对象，本批不承诺崩溃时自动清理。请求内清理失败会保留主错误和清理错误，并尝试写入 `files_pending_cleanup` 供维护人员处理；该表不授权自动删除用户对象，也不是已实现的垃圾回收服务。

`files_storage` 持久化内容位置摘要；存在文件或待清理记录时，禁止无迁移更换 Storage root/driver/bucket。提交元数据时再次锁定并核验位置，避免空库换存储时旧代上传提交到新位置。更换凭据不改变内容位置摘要。迁移内容到新位置需要单独设计和验证，不能直接修改存储根目录绕过保护。

## 本地预览

执行 `./scripts/Start-FilePreview.ps1` 会构建最新后端、只迁移专用预览数据库、重启本脚本记录且启动时间吻合的进程，并验证独立预览账号。默认 WebUI `http://127.0.0.1:4180/home`、API 8120、management 9120。独立数据位于 `.data/file-preview/`，不会重置原有 `.data/app.db`。

地址、用户名、密码、设置令牌及有有效期的 Cookie/CSRF 调试资料保存在 `.data/preview-access.json`；参考站资料由本次操作保存在 `.data/reference-access.json`。二者均应保持 Git 忽略，不能复制到源码或提交说明。预览进程在验收后持续运行，开发下一批时重新构建并重启，以预览最新实现。

现有 console 转发层在登录时保存 HttpOnly/Secure/SameSite 的 IAM CSRF 会话 Cookie，并沿用原有 Origin 与双提交 CSRF 校验。转发不再逐请求轮换原生 CSRF，以免并发写入互相失效。升级前已存在的旧会话可能需要重新登录。

## 验证入口

先实现一批 20 项，再集中验收；失败后只对修复影响范围复测。

```powershell
# 受影响业务与真实 HTTP/数据库/重启验证
go test ./internal/module/files/... ./internal/composition ./pkg/storage/...
# 启动或重启持久预览后，在 frontend 目录执行
npx --yes pnpm@10.22.0 exec playwright test --config playwright.files.config.ts
```

浏览器验收读取忽略目录里的预览资料，不将凭据写进测试源码；覆盖字节一致性、脚本纯文本预览、目录移动、回收恢复、多选、搜索分类、视图持久化、2 MiB 上传、匿名拒绝、拖拽及等待项取消。截图和 trace 位于 Git 忽略的 `frontend/test-results/`，trace 可能包含会话信息，不应提交或公开分享。SQLite 为当前已验证的真实后端；MySQL/PostgreSQL SQL 已提供，但没有在外部实例验收。
