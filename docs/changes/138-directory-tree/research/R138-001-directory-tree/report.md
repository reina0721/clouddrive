基线e2b376423c47650fd62ea30e39961c88b518fcbb，Git干净。前一goal轮是实质进展：137已实现、验证、重启和推送，非阻塞等待。当前主/开发/QA前端运行，后端为137-lf，数据v14。

本地FileWorkspace只渲染分类FileLink、独立工具和PinnedLinks，没有目录树。现有FilesPort.list支持folder-kind过滤、名称排序、显式页码与50条分页，并返回同一真实快照的完整breadcrumbs；服务端按owner、有界元数据和回收可见性处理，不暴露其他账号文件。复用此接口可真实获取各层，不需新Go模块、接口或数据库迁移。每次查询仍受现有searchTreeEntries预算；树不能承诺绕过服务端总量上限。

现有Tree Adapter封装React Aria Tree，拥有键盘、焦点、选择与TreeItemContent，不支持受控expandedIds、展开回调及未加载子项的hasChildItems，因而需要收敛扩展。已安装react-aria-components1.20.0的TreeItemProps包含hasChildItems；官方Tree文档支持受控展开、异步集合和onAction客户端导航。官方同时明确TreeItem受HTML限制不能作为原生a，客户端路由使用onAction；不能伪造原生目录行链接。原分类FileLink仍保留原生修饰键语义。

侧栏折叠当前是Host按账号保存的v1 JSON布尔值，只有FileWorkspace及workspace.test.ts消费。137的同步文档只定义目录视图与文件夹点击；不能把参考设置截图推断为本项目新增树偏好已支持跨设备同步。

## 分类与候选

目录分支缓存、当前路径投影、页码和可见预算属于项目特有应用状态；保留React及现有FilesPort。键盘和ARIA属于成熟第三方能力，继续通过现有UI Adapter使用React Aria，不自行实现角色/方向键或直接从Surface导入第三方。保留当前锁定依赖，无升级或新增；维护主体、许可和安全治理沿用当前已选Adobe依赖及仓库门禁。官方持续维护文档和当前安装类型明确覆盖所需能力，依赖门禁仍纳入最终验证。

比较：继续手写Disclosure/嵌套按钮会重复键盘焦点机制；新增另一套Tree框架会叠加组件、样式、许可与替换成本。useAsyncList适合一个异步集合，useTreeData管理嵌套数据；二者不直接表达本项目每目录分页、祖先链投影和总节点预算。为每分支建立Hook又会在桌面隐藏导航和移动抽屉两处重复请求。选择在FileWorkspace拥有单一项目专有控制器，两种视图共用；不建立通用数据平台、第二客户端或全局可变缓存。

## 推断与决策

扩展Tree窄契约，默认行为保持；新用例显式请求紧凑行及受控展开。Surface持有typed目录分支，Host继续持有网络和设备持久化。根与目录按需读取，单页50；缓存最多1000个真实目录，自动补全祖先的兄弟分支最多20层，超过时保留已验证路径并提供显式载入，不静默丢弃或无限请求。达到总预算明确提示可刷新重置，主列表和路径仍可用。

树的跟随开关与折叠属于本设备侧栏行为，合并为typed v2侧栏偏好，默认不折叠且自动跟随。迁移v1先写新键再移除旧键；不能覆盖137视图同步文档。此选择不声称跨设备同步树开关。账号变化由新Port触发取消与状态清空，旧Host断言阻止写入。

研究门禁通过：接口、所有权、组件能力和预算路径足以形成计划；空参考数据不妨碍以真实本地API验收，但不作参考站功能成功的间接证明。刷新触发器见metadata。

## 验证增量：控件名称与初始化

r2浏览器首轮1通过、6失败；真实上传在树导航期间保留原目标并下载比对通过。三个根展开失败的最终快照仍为未展开；测试未等待初始化完成，早期点击是否被丢失尚未单独归因。根控件使用了不透传aria-expanded的Action，这一点有源码直接证据。改用已有IconAction的expanded契约，并在控制器effect启动前禁用，测试同步等待全局hydration与真实展开状态，不重复盲点。另有Tree按钮名称重复：已安装RAC Tree把expandButtonProps经ButtonContext传递，useLabels关联行名；Adapter又在aria-label中拼入行名，导致实际名称为动作+名称+名称。

定向复核全部三个Tree调用方后，收敛expandLabel/collapseLabel为不含节点名的动作字符串，由RAC关联完整行名。同步迁移files、api-workbench和ui-elements的调用及中英文资源，删除旧函数契约；不自行修改aria-labelledby或键盘逻辑。验证扩大到既有Tree/工作台Tree场景，未改协议、依赖或数据边界。首轮移动场景已通过Axe和页面横向溢出检查，最后断言错误期待根标题My files；改为实际导航目标目录名，保留URL、抽屉关闭和目标标题检查。刷新也补齐已展开的探索分支读取，避免只因清空缓存而误判回收节点消失。

键盘增量：Host全局文件快捷键原本仅排除输入区、菜单和对话框，Delete/F2在treegrid焦点下可能转给主列表。新增语义treegrid排除，不依赖私有组件类名；单位及真实浏览器场景检查主列表已选目录时，树内Delete/F2/Ctrl+A不会打开主列表操作。补验Home/End，不以库支持声明替代实际焦点证据。r3全工作区单位707项通过，lint通过；Web类型阶段曾报生成路由缺失，随后实际文件存在且codegen --check为fresh，未改源码的Web完整类型阶段复跑通过，保留首轮失败，不宣称修复了生成器竞态。

后续DOM事件诊断纠正根展开归因：精确失败场景中没有根按钮click事件。刷新后isVisible立即返回false，测试跳过点击；最终未展开不能证明控制器关闭。等待根按钮可见后再判断其状态，r5真实分页、缓存和根开关场景通过。另一个诊断在相同DOM按钮上观察到一次点击、展开和Tree出现，没有Port重建证据，因此不更改控制器所有权。

r5正式七组为5通过、2失败；一项因未配置隔离管理员访问文件而中止，另一项为Enter动作。移动端关闭抽屉后的焦点问题通过有取消清理的下一帧焦点移交修复，实际320px英文深色、Axe、路由和文件区焦点共同通过。已安装React Aria的useSelectableItem在toggle选择非空时不提供主动作；目录导航需要replace选择行为，Adapter仅增加显式选项，其他调用方默认不变。集合动作使用Tree的key回调，仍由第三方处理按键，不自建Enter监听。

r6六组通过、一组失败：Enter/Space已通过，但Home/End引起选择回调导航，使主列表离开目标。最终导航树显式使用press激活，通过TreeItem公开PressEvents完成鼠标、Enter及Space动作，移除选择回调导航；RAC继续负责焦点和press合成。普通集合保留默认action语义。r7七组全部通过，包含方向键与Home/End不导航、Enter/Space激活、树内主列表快捷键隔离；没有新增手写keydown或DOM访问。
