# R131-001 文件工作区研究

## 问题和可复核事实

基线978a14a，Git干净。只读视觉访问用户指定参考站，在1280×900核对首页、设置和新建菜单。首页当前没有文件，不据此推断文件内容能力。其240px侧栏包含文件分类、共享、回收站、分享、连接、后台任务、离线下载和管理入口；顶部一直提供新建、搜索和账户工具。菜单提供文件、目录、剪贴板上传、文件夹、文本与Markdown，另有绘图类型。本批不把未实现的绘图编辑器算入完成。

本地六页分别位于 `frontend/surfaces/plugins/files/src/*-page.tsx`。FilesPage内有完整侧栏，shared有另一个简化侧栏，downloads又复制侧栏，shares/connections/transfers是独立布局。只有根列表有新建和文件搜索；账户菜单属于AppShell，ApplicationChrome在文件工作区绕过AppShell，因此文件页也缺少该菜单和由AppShell拥有的锁屏生命周期。这些是实际源码事实，不是纯粹颜色差异。

`FilesRuntime`已跨私有路由保持唯一队列，并按账号创建/释放资源；`FileLink`保留修饰键原生链接。`backend.ts`的快捷键监听会先preventDefault，因此只在新Frame里忽略无关回调会吞键，必须在Host支持接受键集合。drop在没有listener时不会创建句柄。现有列表返回配额和真实政策预算；`model.Used`包含当前与历史内容。可复用有界根列表取得摘要，不新增接口、数据库扫描器或伪造0。失败必须显示未知和重试。

复用既有研究R122（tus队列生命周期）、R124（pin与shortcut权限边界）、R127（Drawer/Menu/键盘交互）及R130（分享只读/写入授权与媒体）。它们的相应边界仍适用，但不能把根列表交互证据视为其他页面已经实现。当前新增研究只覆盖跨页面装配。

## 分类和候选

标准成熟能力：Next 16.3.3真实nested layout、React 19.2.8、已有state-foundation、UI Adapter的Menu/Drawer/SearchBox、Host账户菜单与tus队列。项目特有逻辑：文件分类链接、目标文件夹、配额呈现和刷新修订。继续复制各页会维持多个不一致的入口；新增Router或UI框架会重复维护导航、状态与样式。选择重构承载位置至Next layout，保留已有窄Port；不更换依赖、不引入通用框架。

官方Next布局文档确认共享layout保留状态；安装版文档和官方useSearchParams确认客户端查询读取与Suspense要求。框架已支持layout机械生成；RouteTransition无pathname key，不会主动重挂layout。现有依赖版本、许可、安全与生产采用沿用既有锁文件和技术选型authority，本任务不升级库，因此不重新研究不相干候选。最终仍执行依赖与产物门禁。

## 推断、边界与验证

推断：共用导航及全局动作能直接减少用户在页面之间来回跳转，且不要求重构文件业务后端。Frame只在私有文件layout生效；公开分享不变；Host继续拥有DOM、账户、localStorage与原生选择器，Plugin仅消费类型化契约。折叠偏好按账号保存，与已有文件视图偏好分离，错误可见。

创建和上传必须显示并核对自有目标文件夹；其他页面默认自有根目录，不把分享页或分类当写入目标。回收站禁用新建。创建失败保留输入；目录上传复用路径检查；候选取消时释放。队列徽标只称当前已载入的活动项，不伪装服务端全部任务数。锁屏是已有客户端隐私遮罩，不成为服务端授权机制。

研究门禁通过：所需承载路径和错误/资源边界已有证据，剩余参考站空数据不妨碍当前有界计划。刷新触发器见metadata；实施只做增量漂移检查。20项先接通，再集中进行类型、lint、单元、构建、性能、桌面/移动/深色/英文/键盘与实际写入回归。预览库不得作为测试数据集。


实施验证补证：既有 `auth/unlock.ts` 在真实后端模式明确返回 unsupported，只有mock可本地密码解锁。本批保留该边界：文件页可锁定遮挡并禁止背景交互，真实部署通过退出并重新登录恢复；不把密码原地解锁记为已实现，也不调用登录伪装只读复核。此项属于复用已有锁屏的明确限制，未新增认证接口或授权行为。
