# R128-001 文件版本历史

## 事实与证据

基线03724fe，Git干净。真实参考站只读主页依旧空文件；已看实际截图，不声称观察过有内容的历史面板，也未在参考站创建测试文件。官方[概念](https://docs.cloudreve.org/zh/usage/concept)明确不可变Blob、版本保留、文件大小与占用不同、复制共享Blob关联。项目README/scope仍明确版本历史未实现。

现有Service.ReplaceText写新不可变对象并递增内容版本，失败补偿本次候选。旧对象因副本引用不删除，但没有可检索历史元数据，不能据其存在推测历史。Transfers.commit是普通分块和WebDAV流式发布公共事务；现有ExpectedEntryID/Revision仅WebDAV可用。stream_ingest按新减旧预留，dav_mutations COPY覆盖是另一条真实内容替换路径。copyTree复制不可变内容引用、重置内容revision；需调整才能继承历史。repo具体entryRecord负责annotation JSON，不把字符串交给业务；所有写入在storage/owner锁与WithinTx内。公开分享/DAV输出Entry的公开投影，私有字段必须隐藏。

## 技术与承载选择

|候选|收益与限制|决定|
|---|---|---|
|现有Storage不可变对象+GORM owner事务+标准encoding/json|覆盖local/S3；可将有限历史作为目录项事实原子保存；无需第二连接/worker；必须控制行内大小和账号快照预算|保留成熟基础；项目只实现业务版本关联、预算和恢复规则|
|[S3桶Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)|成熟原生保护，但本项目每次新键，本地存储无此能力，且不能表达应用owner/改名/复制/配额|不作为应用版本authority，不修改桶或Storage公共契约|
|独立版本表和查询port|适合大量历史、独立索引、引用GC；当前仅每文件20条、owner1000，额外表/回调装配不能消除原owner事务和所有写入路径迁移|当前有限聚合使用类型化JSON；超过边界或加入GC时重新研究独立表，不叠加兼容层|
|Git/通用内容版本框架|更适合仓库差异、分支与合并，不能代替现有文件授权/配额与二进制流生命周期|不引入；并排文本使用现有文字显示，不自研diff平台|

Go1.26.10标准JSON、GORM1.31.2、Huma2.39.1、现有tusd/tus-js-client和HeroUI均沿既有受控边界；本任务不新增依赖，不将当前项目版本称为上游最新。[GORM事务](https://gorm.io/docs/transactions.html)复核错误回滚语义；实际一致性仍以项目WithinTx实现和集中测试为准。许可证/API升级/安全演进不因本批新增依赖而改变；新逻辑为files特有事实，不做通用版本平台。

## 推断与边界

有界行内历史在当前每条最多20/owner1000约束下可复用现有entry聚合和owner锁，复制可显式深拷贝历史而不靠隐藏反向查找源对象。每条编码硬预算64KiB，所有API创建/复制均检查owner历史总数；普通查询的内存不会随着无界保留增长。尚无此实现和性能结果，集中测试必须证明升级、历史配额、冲突与全部写路径。

配置开启保留时，每次有效覆盖旧版本留存，空间增加新内容大小；关闭只影响未来覆盖，已有历史不丢。恢复明确保留当前，即使未来保留关闭也不丢恢复前内容。到达预算拒绝新保留，不自动淘汰。历史引用可由产品用户明确确认后移除，只释放逻辑引用占用；物理对象沿项目既有无通用GC事实保留，不能宣称磁盘立即回收。我们不删除用户历史或数据，只在命名隔离验收环境创建/清理自有fixture。

研究门禁通过：写入、复制、存储和UI接入路径已定位；以上限制不阻碍本批20项计划。刷新触发器见metadata。升级前没有记录的旧版本、共享访客历史权限、自动GC/差异算法不是本批已实现承诺。

## SQL细节复核

MySQL历史列采用TEXT及表达式默认值('[]')；[官方8.4手册](https://dev.mysql.com/doc/refman/8.4/en/data-type-defaults.html)要求TEXT默认值使用括号表达式，8.0.13以前不支持。当前MySQL未实例验收，不能声称支持更早版本。统一编码上限65535字节以匹配TEXT；SQLite/PostgreSQL也执行相同应用校验。

## 集中验证触发的恢复边界刷新

上限为1时，如果恢复既保留所选旧关联又新增恢复前当前关联，会无法执行任何恢复；还会重复增长逻辑占用。按官方不可变内容关联语义修正为“提升所选关联、当前退入历史”，仍递增内容CAS和历史CAS，空间不变且保留恢复前内容。属于本批恢复语义完善，不增加新依赖/模块/副作用；UI与需求同步说明旧版本号提升后不再作为旧关联单列。日期是保存时记录的文件修改时间，不推测升级前缺失的内容原始时间。

集中媒体实测：Go标准http.DetectContentType对WAV返回audio/wave，浏览器Host统一为audio/wav后音视频旧版实际解码/播放/关闭释放通过；替换内容类型不能沿旧目标扩展名直接认定。降低保留配置时恢复为等量提升，验证无需新增配额，但仍保留编码与类型硬边界。

MySQL历史down明确使用ENFORCED，避免旧版本静默忽略CHECK。依据[官方CHECK说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)，8.0.16以前CHECK只解析不执行；本批SQL回滚保护要求8.0.16+，TEXT表达式默认值另要求8.0.13+。这是静态适用边界，不代表已进行实例升级验收。
