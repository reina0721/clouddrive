# R125-001 高级检索研究

## 问题与快照

需要确认参考站真实搜索条件、当前List是否能承载、扫描/权限/排序/分页如何保持一致，以及视图和选择是否缺少实际交互。2026-11-04基线7aeded2，工作区干净。已检索docs内metadata并读取R120-001/R121-001报告：文件模块、Host/Surface、IAM及内容租约边界仍有效；其工具链和实现数量已过期，以当前代码及124验收为准。不重开已验证的分享/传输/WebDAV技术选型。

## 参考站事实

CUA只读查看用户指定首页，已有登录态。首页为灰侧栏、白色主内容，顶部“新建/搜索”，第二行面包屑与刷新、视图、排序。视图菜单显示网格/列表/画廊、缩略图开关、分页大小。排序实际为名称、大小、修改及上传时间各两方向。搜索打开输入面板，高级搜索包含路径、可添加关键词、“忽略大小写”“需包含全部关键词”；添加条件菜单显示文件类型、文件大小、创建/修改日期，以及标签、元数据、媒体和自定义属性。查看后取消草稿，没有修改参考站数据或偏好。

这些是界面观察，不等于已实测全部条件的后端语义。没有参考站文件样本；日期边界、目录子树及多选行为由本项目形成可验收设计。标签/媒体索引没有当前实现，不能用空选择项冒充支持。

## 当前实现事实

- service.Service.List从Repository.Read读取完整owner集合，Query只有parent/search/category/trash/sort/desc。名称是ToLower包含匹配；文字或分类使查询跨当前目录。四种排序有ID平局项，没有目录优先或普通列表分页。
- Repository.Read通过Kernel数据库租约，读取后复核存储位置；repo.loadBoundedEntries已在导航和分享检查中使用真实LIMIT+1。可以扩展消费方Repository.ReadBounded，让List在同一实现中使用预算，不必为新搜索建立第二个服务。
- 文件可见性同时依赖自己和祖先；在数据库分页后才判断可见性会产生漏页/错误总数。索引字段过滤也不能替代owner与祖先检查。
- FilesPage的list视图仍是文件卡片换方向，没有列头/列可见性；画廊只有每屏预算，普通列表一次渲染所有项。只有checkbox逐项多选，没有Shift范围、修饰键切换或文件名的方向键焦点。
- Host.loadPreferences仅保存view/sort/desc，默认值在Host和Surface重复。键盘与DOM焦点由Host订阅，Surface不应引入document或会话全局变量。Routes通过URL参数传递当前检索，Provider和上传队列跨应用路由保留。

## 分类、成熟候选与技术结论

元数据匹配、私有树范围和文件选择是files业务规则，非新的通用搜索平台。Unicode子串和UTC日期采用Go1.26.10标准strings/time及现有NFC；数据库预算复用GORM1.31.2的Limit/WithContext。当前安装源码定位：strings.go Contains约62行/ToLower约727行、time/format.go Parse约1023行；GORM chainable_api.go Limit约343行、gorm.go WithContext约363行。官方[查询文档](https://gorm.io/docs/query.html#Limit--Offset)复核LIMIT和Offset语义；网络Go包页版本可能高于当前工具链，不据此升级。

比较三条承载路径：当前无界Read继续叠过滤没有资源收益，拒绝；GORM有界快照+标准库匹配能保留各数据库一致的短词/NFC/祖先语义，采用；把条件全部推到SQL或FTS需要额外处理不同数据库collation与被回收祖先，当前无经验证的收益，不采用。

[SQLite FTS5官方说明](https://sqlite.org/fts5.html#the_trigram_tokenizer)指出trigram全文查询短于3个Unicode字符不匹配；本任务必须支持单字/短词。其外部内容索引还需应用维护一致性，无法替代权限与目录状态检查。FTS5是成熟SQLite能力，但与此处有界元数据精确条件的收益不匹配；不引入分词、影子表、重建worker或仅SQLite可用的行为。

保留候选的维护/演进、安全与生产证据沿用123/124已安装依赖快照；当前官方源码/文档只复核所用稳定API。标准库BSD与现有GORM MIT许可无需新增清单。三方言兼容、取消/错误链、测试注入和现有日志边界继续可用。FTS5本身成熟不等于本项目已启用或验收，不能凭官方能力宣称可接入。标准库方案不拥有资源，易观测受控失败，未来可在ReadBounded窄契约后替换实现；退出条件为内容全文、多机或真实规模超过树预算，此时重新研究索引与承载架构。

## 资源、配置与失败

List借用数据库，限定每账号默认10000条（可调小），超出明确413，不返回截断成功；树/匹配/排序循环检查ctx。使用ID索引和可见性/子树归属记忆避免重复全表查父，不能用无界递归。过滤/排序后才分页；未分页为明确的pageSize=0，用于目录选择等现有调用，不是旧实现回退。

关键词最多8个、扩展名最多16个，单项255字符以内；整数大小约束可为0，缺失不等于0；时间为UTC下界包含/上界排除。普通页最大200项；未分页总集合仍受树预算限制。HTTP错误保留当前invalid/large/missing/canceled语义，不记录原查询、文件名、完整URL或偏好。无新连接、worker、端口或迁移；files配置RestartRequired。所有可见性/权限仍由files和IAM拥有，搜索不读取原分享内容。

## 门禁

实施定向补证：本机Node标准http.maxHeaderSize实际为16384字节。8个255字中文关键词在URL中展开后可能超过该预算，因此UI条件编解码增加4096个百分号编码字节的总上限，并在对话框关闭前验证，过长保留输入并提示减少关键词；Host直接构造查询也执行相同约束。普通名称条件最长255字符与该上限合并仍留有头部预算。没有增大HTTP保护、引入另一搜索端点或回退实现。UI日期编码只接受UTC整日规范形式，防止再次打开日期控件时悄悄取整；原生协议仍接受RFC3339时刻。

关键证据足以形成F101–F120计划，研究门禁通过。剩余未知不妨碍有界实施：参考站没有样本，不承诺其所有搜索条件、文件内容全文、标签或媒体索引；外部数据库不作实测承诺。UI使用已有组件，视图偏好按owner保存并验证，非法数据明确提示，不创建第二套全局设置。实施仅做基线漂移核对，未触发刷新条件不重复研究。
