# ADR-001：采用 tus 与独立业务控制面

日期：2026-11-03；状态：按用户当前goal授权进入实施，验收尚未完成。研究：R122-001。后续变更通过新ADR取代，不将本文当成当前功能已完成的证据。

## 问题

现有bytes上传与页面局部队列无法承载大文件及跨刷新接续，直接提高32MiB上限会将整文件缓冲压力传播至浏览器和服务器。另建外部网盘或直传云对象服务会引入第二套资源、身份及部署链路。

## 决策

采用tusd2.10.1的核心协议与filestore，不复制offset协议；采用tus-js-client4.3.1并经Host Port隔离。业务控制端点创建、暂停、恢复、修正目标、完成和取消会话，核心HEAD/PATCH消费业务已经创建的URL；不宣称支持未开放的Creation扩展、Concatenation或IETF草案。

暂存位于明确配置的同机持久目录，使用gofrs/flock0.13.1的同步OS独占锁统一覆盖协议与发布。tusd/filelocker因公开退出语义不足而不采用，原因保留于研究定向复核。所有永久内容仍经现有Kernel Storage租约，新增真实流式读写与HTTP预算，不新建S3客户端。

浏览器用noble-hashes2.4.0增量SHA256识别重选源，服务端crypto/sha256复核；不将文件名或时间当内容身份。所有业务状态、配额、最终目录项及清理预算归files；协议适配器不拥有账号或权限。

## 后果与退出条件

需要数据库增量、API与Host单轨迁移，增加本地暂存磁盘预算和上游依赖。永久对象与数据库无法做跨资源事务，必须先持久化发布意图，再幂等写不可变对象并原子提交目录项；清理错误保留可重试状态。

当前方案依赖同机持久暂存和OS锁，不可直接扩展为无共享磁盘的多主机部署。直传云对象、>5GiB、跨主机作业或更改公开协议时重新研究。替换tus只迁移活跃暂存、核心协议端点与Host实现，不将第三方结构写入永久Entry契约。
