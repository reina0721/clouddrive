# R139-001 时间边界

## 已核验事实

基线5b9c1906461cc2a12163844a8bcadf97f5d252f2，Git干净；138是已交付的实质进展，不是阻塞等待。主/开发/QA服务仍运行，原两库schema14。检索既有metadata后，复用R137偏好所有权及R138工作区事实，但二者不包含时间转换实现。

参考站偏好显示IANA时区America/New_York并说明默认跟随系统；同页还有版本保留扩展名与数量设置。本轮只读截图，不更改参考账号配置，也不由空文件目录推断时间功能成功。本地存在完整localeRegion及账户服务端时区字段，文件插件却混用固定UTC的列表日期、浏览器本地时间和未传时区的formatDate。分享自定义时间拼接Z，实际为UTC壁钟；后续完整文案复核确认日期和时间标签原本明确标UTC，不能称为未声明的UTC转换。本批将其改为所选时区输入，同时同步移除旧UTC标签并显示草稿实际时区。

i18n/format.ts是既有Intl边界；PreferencesPort提供订阅和持久化结果，Surface可用useSyncExternalStore，无需第二全局store。纯日期formatDateOnly明确用于不随时区变化的日历日期，不可拿文件瞬间直接套用。现有时区候选只有auto及三个IANA时区，账户编辑则是任意文本；模型仅检查字符串，尚无有效IANA边界校验。

UI Adapter已声明@internationalized/date3.12.3；安装包Apache-2.0、sideEffects:false，类型和实现支持parseAbsolute、parseDateTime、toZoned及reject/earlier/later。官方文档明确DST跳过和重复时间的处理。当前官方安全公告页面没有已公开公告，不把该结果视为无漏洞保证；当前官方文档仍维护该API。一个官方仓库编码路径及猜测releases路径读取失败，不把它们计为成功证据。

## 候选与承载判断

|能力|选择|原因与退出边界|
|---|---|---|
|瞬间格式化|保留标准Intl，通过i18n窄函数|无额外时区数据库或生命周期；格式、无效值和时区错误可独立测试|
|壁钟到瞬间|复用项目已有Adobe3.12.3，向i18n显式声明同版本依赖|成熟解析和DST消歧，浏览器生态及现有DatePicker生产使用证据；不升级、不引入第二日期栈|
|手写偏移算法|不采用|Intl没有壁钟反算，反复猜偏移与DST边界会重复造轮子|
|新增Temporal polyfill或Luxon|不采用|现有库已覆盖真实需求，新栈增加下载、许可、维护和替换成本，缺乏收益|
|偏好所有权|保留PreferencesPort与现有账户偏好|框架契约够用，不新建文件专有时区；通用区域设置的设备/账户保存范围保持现状|

Go版本不适用于客户端库；当前Node/TS与现有组件已使用3.12.3。日期库的第三方类型只停留在i18n temporal入口，Surface只见字符串与判别结果；无外部I/O、资源关闭、后台任务或日志需求。转换错误完整转换为invalid/gap/overlap/zone，不打印用户日期或原始异常。依赖治理允许边界需显式扩展到i18n。

## 决策与局限

显示与转换分离：i18n的纯Intl入口不加载日期转换库；分享编辑的惰性模块才使用temporal入口，避免挤占已接近上限的初始路由预算。输入固定记录创建草稿时的实际时区，后续显示偏好变化不能无提示重解释同一草稿。跳过时间拒绝；重复时间要求显式选第一次或第二次，不默默选默认。相对有效期仍按经过的小时计算，keep保留原瞬间及秒精度，不因显示或重新保存而改期。

研究门禁通过。当前承载边界足以实现，无需Go接口或数据迁移；浏览器时区库覆盖以实际运行环境为准，不自带IANA更新数据库。版本保留需涉及真实覆盖/上传/WebDAV与配额事务，不能顺手放一个设置冒充接通，保留后续研究范围。
