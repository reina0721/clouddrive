# 引擎、任务与发布的待定设计边界

本文是详细设计的研究输入，不是已确认实施方案。

## 聚合与数据流

任务需区分来源准入、元数据、等待文件选择、下载、验证、转存及终态。当前HTTP单child不变成BT的虚构child；真实文件清单形成前不创建零字节候选冒充元数据。选择形成后，逐文件候选与任务共同受owner事务、字节及数量预算保护。需决定任务组预留与既有Transfer计数的关系，再给出追加schema；禁止直接放宽全局计数。

最终存储仍由files Storage和发布事务拥有。引擎随机块暂存与tusd顺序暂存不能互相穿透。若引入独立引擎暂存，须明确物理字节上限、双份暂存期间预算、只读完成内容契约、symlink/reparse及路径限制。目录创建与所有文件原子发布，或明确逐项回执，必须先选择一种可恢复语义；不得以一个成功child代表整任务完成。

## 引擎及账号隔离

当前尚未选择引擎。嵌入式Client需要可注入网络/日志、资源关闭和每任务存储隔离；不能靠共享可变全局Logger或替换依赖缓存文件隐藏问题。外部RPC需严格超时、响应上限、受控地址、Secret、协议版本和重启身份验证，不能把前端参数原样转成RPC调用。

外部引擎的同hash去重不能直接视为本项目的幂等：幂等属于owner和clientKey。需要验证按任务ID隔离、按节点/hash串行调度或其他有证据的机制；任何复用都不得暴露另一账号的下载目录、进度或凭据。暂停/删除必须只控制绑定的实际任务，旧RPC句柄不能在daemon重启后命中新任务。

## 生命周期、失败和配置

继续通过files Contribution、Scheduler和generation准入组织后台工作，不另建常驻万能worker。构造无下载副作用；Start、取消、Stop与Wait的顺序以及节点故障策略须在选型后落实。用户意图与租约围栏持久化；来源故障、元数据错误、预算失败、权限/目录/写锁改变、存储失败、取消和清理失败分别保留语义。

引擎/节点配置应由files拥有并经composition显式注入，不能从调用方随意读取环境或创建第二套客户端。默认值、Secret来源、network scope、restart/reload、节点身份变化和孤儿任务处理须具体定义。实际出站策略需要覆盖tracker、peer、DHT和webseed；不能把HTTP来源的安全测试扩大为外部引擎已受同样限制。

## 文件影响与验证计划

预计影响files model/repo/service/adapter/handler/HTTP/config/migration、composition装配、生成契约以及前端离线列表与新建/文件选择面板；精确路径与接口待选型后补齐。默认不新增通用pkg或Kernel资源。

研究通过后先记录revision与Git增量基线，再实施已列任务。20项接通后统一使用受控的本地种子/磁力/真实seeder验证文件字节、选择、同hash双账号、暂停、进程重启、节点失效、旧worker、额度、目标变化和清理失败，随后做相关Go/前端/浏览器检查。保护当前两库和存储，先一致性备份，再仅追加迁移；禁止回滚或重置用户数据。完成构建后重启已归属的三个预览并更新忽略的访问文件，保留无关进程。
