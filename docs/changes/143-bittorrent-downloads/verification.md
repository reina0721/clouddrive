## 后端与真实传输

- aria2 Adapter定向用例通过：HTTP错误信封、准确的缺失分类、响应大小、ID和目录围栏、回执丢失与确定未发送分离。bencode定向用例通过：原始infohash、多文件清单、路径冲突、递归及长度边界、磁力参数注入。
- Go产品协议夹具验证双账号、种子与磁力、两秒以上仍保持同一领取、拒绝空选/重复索引/旧版本、多文件原子发布、目录及字节、暂停选择、恢复、删除记录和保留数据；独立验证本人已用空间与所选字节的配额，实际WebDAV写锁阻止所有候选发布，解锁后同一任务重试成功。
- 本机aria2 1.37.0与Transmission 4.1.4经受控tracker真实交换；无Webseed。最终复验解析两文件清单、选择前0 payload，实际速率采样119841 B/s，暂停时无活动native job，持久记录114688 B。应用与aria2均重启，节点session改变且旧暂停句柄没有复活。关闭种子源后，恢复任务实际重新校验并复用131072 B，再恢复做种完成下载。
- 两个真实IAM账号对同一infohash选择不同文件；产品实际发布各2097152 B，每个文件的SHA-256与种子源一致（`5256ec18…e6d84b5`、`85a6e0cd…a975`）。跨账号读取/控制被拒绝；删除任务记录后文件内容仍一致。产品RPC夹具还验证节点不可达时无发布、节点恢复后重试仍使用原任务。
- SQLite迁移测试逐表比对原v16数据；存在BT记录时v17 down脚本拒绝删表。MySQL/PostgreSQL迁移随三驱动校验和管理，本轮真实运行环境为SQLite。

## 实际问题及复核

1. GID数据库列需要显式映射；服务端流写入使用既有deferred暂存契约，再有界写入、Seal与原子发布。产品协议夹具覆盖该路径。
2. [aria2固定版HTTP实现](https://raw.githubusercontent.com/aria2/aria2/release-1.37.0/src/HttpServerBodyCommand.cc)会将正常JSON-RPC错误放在HTTP 400等响应中。[固定版状态实现](https://raw.githubusercontent.com/aria2/aria2/release-1.37.0/src/RpcMethodImpl.cc)为终结结果提供dir。Adapter在有界信封内验证请求ID、协议和确切错误，再判断缺失；终结状态不依赖getOption。
3. 通用Execution两秒预算使真实BT元数据反复被打断。使用现有命名策略绑定持久任务预算；夹具延迟超过两秒，真实磁力随后通过。
4. 真实节点终结回复出现任务总量2097152 B、已完成2097152 B、已选文件逐项完成量0；保存文件哈希匹配。改为校验终态、总量与清单后，仍实际逐文件校验长度和摘要，再发布。
