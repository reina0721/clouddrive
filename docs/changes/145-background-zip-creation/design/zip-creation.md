# 队列及发布

新增私有 `POST /files/archive-tasks/zip`。请求包含客户端键、来源 ID、文件名和目标文件夹。复用账号写入权限、所有者事务及任务配额；已存在的键仍按原始请求比较。事务建立有界 ZIP 成员列表，验证可见性和安全路径，记录排序后的来源签名。签名覆盖源成员 ID、路径、大小、版本和对象。目标目录身份按 ID 使用，提交时与发布时均校验可见性和同名。

后台领取后按当前来源快照复核签名，用 Go 标准库 Deflate 生成 ZIP。输入及输出使用现有归档预算，输出同时受单文件大小限制。落存前记录候选对象键。发布事务重新核对来源签名、目录、配额及写锁，将新文件和任务结果一起提交。取消、超时、清理、日志及重启沿用 v18 语义。

v19 向原表追加类型、签名和结果文件 ID，历史行默认解压。回退前检查是否存在压缩任务。任务页为创建类型显示 ZIP 名称和结果链接，复用手动及自动刷新。文件选择区与单项菜单使用同一个表单。同步打包下载保留 Store 编码和响应契约。

全部行为接通后，集中验证真实 ZIP 字节、层级、版本变化、预算、迁移及旧流程，运行桌面和移动视觉检查。
