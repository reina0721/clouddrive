## 当前代码事实

- Entry仅有内容/目录/引用字段。repo的entryRecord直接别名Model，loadEntries、loadBoundedEntries、Connections.entries直接转换；新增结构字段不能继续靠别名隐藏ORM/JSON映射。
- ChangeMany在既有数据库WithinTx内先锁storage/owner，再读快照、保存受控变化集合；可增有界同一事务入口，复用现有租约，不另建连接或锁服务。
- List已经LIMIT+1限制一万条，查询树支持迭代可见性、过滤、分页。新标签/属性过滤可在同一有界快照完成，不需要跨数据库JSON查询方言。
- copyTree复制Entry值，但新增slice必须独立克隆；WebDAV通过同一复制用例。transfers完成覆盖重新构造Entry，必须显式保留原注解，否则覆盖会丢属性。普通改名/移动、文本替换及回收恢复沿现有条目事实，需回归验证保留。
- 公共Entry输出、DAV和分享使用现有窄契约。本批注解字段在Model的JSON中隐藏，只在私有注解接口及受限列表摘要中公开，不能随普通Entry自动泄露。
- 现有DrawerSurface、DialogSurface、TextField/SelectField和FileGlyph可复用。Host拥有网络、剪贴板和账号失效；Surface不读DOM或自建客户端。

## 分类、候选与承载判断

注解规则属于项目特有业务，字符串/JSON属于标准库，持久事务属于成熟GORM及已有数据库能力。保留Go1.26.10 encoding/json、项目NFC正规化、GORM1.31.2和Huma2.39.1；继承有效的工具链/依赖基线，不新增第三方或后台资源。持久JSON字符串和解码在Repository边界，Model仅用标准JSON测量业务字节预算，不拥有存储字符串或ORM类型。

GORM serializer/datatype JSON是成熟候选，但把其标签或类型放入当前Model别名会扩大技术耦合，且不能替代业务CAS、保留/复制和输入预算；选择具体record映射有可验证收益。独立标签平台、EAV/全文引擎会增加资源、跨表一致性和退出成本，当前仅有私有有限属性，收益不抵成本，暂不引入。现有事务、composition、授权和生命周期适合作为承载；无新Kernel能力、连接、goroutine或隐藏回退。未来需全局模板、媒体索引、多机协作或超一万条时另研究。

## 计划影响与风险

新增v9只为files_entries添加有界注解JSON与独立revision，旧v1–v8摘要不变。旧行明确为空注解/revision0，用户内容不重置。新record完整映射所有旧字段，必须以HTTP/SQLite/重启、原文件逐行保留、分享/DAV隔离、复制和覆盖验证防止漏字段。down guard拒绝丢弃已使用注解；本任务不执行用户库down。

注解总JSON默认最多2048字节、标签最多8个、自定义属性最多8个，字符与键空间有限；账号树一万条的序列化注解上限约20MiB，解码还会有对象开销，故新读取/批量修改均使用有界树和取消。普通分页最多200条只带标签/个性化摘要；非分页目录选择不附全量注解，画廊通过一次当前屏批量摘要查询保持相同能力，避免逐条详情扫描。超预算必须明确拒绝。没有无界索引或通用元数据引擎。

同条目注解版本CAS；批量标签最多100项目，整批原子，不把部分成功藏起来；已有值和草稿在错误时保留，不能静默覆盖。个性化颜色严格限定六位RGB，Emoji为受限Unicode文本；不接受CSS、URL或系统键。日志只沿当前operation受控分类，不记录标签、属性值或原始错误。研究门禁通过：调用方/所有权/保留路径已定位，剩余参考站空态局限不妨碍此私有范围计划。
