# R188-001 图片标注叠层

[Cloudreve 官方截图](https://docs.cloudreve.org/assets/file-apps-image-editor.DA9QZGmM.png)右侧工作区的标注栏包含 Image，和文字、几何形状及画笔并列。画布中的选择框和下方工具区可见。现有水印只有固定锚点，无法作为普通标注拖移和排序。图片水印、形状标注以及版本保存分别由 R185-001、R183-001 和 R187-001 记录。基线 `8a51b6e` 中，这三条路径都汇聚在 `frontend/apps/web/src/files/image-edit.ts` 的 Canvas 绘制入口。

位图使用现有签名及尺寸读取边界。Canvas 2D 标准能力可完成透明像素合成、中心旋转与统一导出。Filerobot 和 Konva 适合接管整个交互舞台。此场景只增加一种标注对象，替换舞台会重复图片坐标、键盘选择、历史与发布契约。决定保留现有 Canvas、图片尺寸依赖与装配方式，扩展项目特有标注模型，无新增第三方依赖、通用解码器或 Go 能力。源图、覆盖层和输出分别由编辑器、共享资源池和现有上传队列负责。

Cloudreve 白板是独立缺口。2026-11-10 npm 稳定版为 0.18.1，所查[导入问题公告](https://github.com/advisories/GHSA-v2vq-3h6w-9r3c)没有给出已修复版本。白板待独立复核 SDK，图片标注无需该依赖。

截图只证明入口和工具布局。具体尺寸、旋转档位、资源上限和合成行为属于本项目设计，用隔离预览实测。若需要远端图片、服务端渲染或可重开分层文档，须重新验证契约。
