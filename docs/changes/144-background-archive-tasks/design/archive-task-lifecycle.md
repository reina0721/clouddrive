# 后台归档任务生命周期

## 接入与持久状态

在 files 模块内新增专用仓储、用例、HTTP 绑定和数据库 v18，新增表及索引，回退前检查表为空。复用现有存储身份锁、owner 锁、文件写锁、调度器和账号写权限投影，不增加依赖或服务。排队任务持久化来源 ID/版本、选择、目标、冲突规则和客户端幂等键。记录上限为每账号 50 条、全库 2000 条，终态且无待清理对象的记录可清理。单次请求和存储编码各有 64 KiB 预算。账号和任务键组合隔离记录保留期间的请求重放。

调度以有界的一次调用读取候选并事务领取。领取写入围栏和到期时间，同一数据库并行的归档执行有上限。执行时间短于租期，校验当前 IAM 写权限并沿用归档解析资源限制。取消只接受尚未领取的任务。排队状态跨重启保留，过期的处理中任务标为中断而非自动重放。阶段和结果只显示已经发生的事实。

## 原子发布与对象所有权

复用现有归档提取计划、解析与目录发布校验。首次写内容前，事务保存本次候选对象键；候选只用于该次领取。发布事务校验领取围栏、来源版本和目录链，写入目录项并同时保存成功结果和清除候选账。成功事务不经过清理。失败事务核对仍是同次领取才写终态。候选清理独立确认终态，延迟至写入期限后，用同一存储身份做有界重试。提交返回错误后重新读取状态，避免删除已经发布的对象。

结果 API 只包含当前账号可见的任务、目标、计数、时间和稳定失败码；密码、对象键与底层错误保持内部。调度边界记录低敏阶段和失败类别。原同步路由与密码处理保留，其输入不会进入持久任务。

## 接口、页面及验证

新增排队、按账号列表与详情、排队取消、完成记录清理接口。文件区添加独立后台任务页，沿用现有侧栏和页面控件，解压表单复用目录选择。观察 UI 的空态、刷新布局和桌面与移动交互。实现全部 20 个行为后集中验证 SQLite 旧库迁移、并发领取、围栏和对象补偿、权限、浏览器及实际重启。MySQL 与 PostgreSQL 的运行验证随可用实例记录。
