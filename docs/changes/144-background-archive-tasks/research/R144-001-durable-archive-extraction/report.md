# R144-001 后台解压的文件发布与任务记录

## 事实

- 参考站桌面 `/tasks` 有独立侧栏入口、标题旁手动刷新、右侧自动刷新和页面中央的空状态。该账号未显示任务记录。截图只记录页面空态，行内容和终态语义由本项目的真实工作流决定。
- Cloudreve 官方工作流路由提供任务列表、阶段进度、压缩、解压及离线下载。官方文件应用文档确认 ZIP/7Z 可按所选成员解压。[工作流源码](https://github.com/cloudreve/Cloudreve/blob/master/routers/router.go) · [文件应用](https://docs.cloudreve.org/en/usage/file-apps)
- 当前 `internal/module/files/service/archive_extract.go` 在请求中完成解析、构造发布计划和写入，事务内重新核验来源版本、目标目录链、名字、空间和树预算。`repo/repository.go` 的 `saveEntryChanges` 同时执行 WebDAV 写锁检查。
- 当前 `internal/module/files/module.go` 注册现有定时调度；BT 路径使用 `persistent-task` 单次策略，业务自己控制超时和状态。`pkg/execution` 的执行记录不能与文件发布共用数据库事务。
- 当前归档读取复用 R133-001 选定的标准库 ZIP 和隔离 7Z 解析。没有改变解析器候选、版本和资源模型。`internal/composition/files.go` 已将后台账号操作投影到当前 IAM 文件权限。

## 推断与方案取舍

保持已有调度、数据库、存储与解析边界，在 files 内增加归档任务状态和有界领取。直接增加数据库任务表可用同一所有者事务提交目录项与成功回执，外置队列仍需要文件事务围栏与跨资源恢复，还会增加部署和连接生命周期。本批没有独立队列所需的跨模块消费场景。继续使用现有调度与成熟的数据库事务即可满足已观察的流程。

有密码的操作仍通过请求内有界解压完成，后台输入不含密码。已有归档接口保留原返回契约，页面提交可显式选择后台；不在本批设计凭据托管。后台状态使用可证实的阶段，成功只在实际发布后返回，处理中断以有界失败记录呈现。

## 局限与刷新

参考站空态不能证明其取消、恢复和失败细节，后台写入时限、权限重查与有界任务记录属于本项目约定。ZIP 创建和更广泛的任务聚合另行研究。若存储写入、文件锁或跨节点约束变化，按元数据触发器定向复核。
