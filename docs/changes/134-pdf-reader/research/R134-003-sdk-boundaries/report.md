# R134-003：真实SDK边界与修正

事实：官方PDFViewer的annotationEditorMode setter先启动异步UIManager更新，最后才发送annotationeditormodechanged；setter返回不等于工具可用。命令改为等待该公开事件，父会话期限覆盖等待，关闭移除监听并取消，Host保持交互冻结到实际确认。6.4.299声明将getter错误推断为setter对象，实际源码返回数字枚举；仅在Host/SDK边界以unknown校验，不复制SDK或访问私有字段。

真实3000×3000图像PDF由ReportLab/Pillow生成并经pypdf确认尺寸，源仅约28KiB。实际Chromium及上游legacy Node诊断显示maxImageSize会使超限图像不进入操作列表；即使stopAtErrors=true，getOperatorList也可能解析为零操作，不能把它当成可靠的typed超额失败。Node现代build还要求额外浏览器API，诊断使用官方legacy build；production仍是显式module Worker，不允许假Worker。既有页数/源字节/输出/大纲/缩略图/工作期限的明确失败路径没有因此改变。

结论：保留成熟SDK的图像像素限制和正常修复行为，不patch上游、不hook其console或私有Worker协议，也不自研第二套PDF扫描器。阅读界面明确显示图像像素预算及“超限图像不会显示，完整内容请下载原件”；不把预览承诺为所有PDF的完整还原。图像限制测试使用红色真实图像，确认超限图像被省略且用户有明确说明；其余超限仍验证明确失败。不是隐藏回退，也不把“省略”写成“已完整读取”。

公共客户端新增limit错误须保留真实来源，不把客户端流量上限伪造为服务端HTTP413。文件边界映射large；三个不使用有界Blob的身份调用方原样向上传播该契约外错误，避免扩展身份业务状态或丢失原因链。

这些是原I134的边界与失败语义修正，20项范围不增加、不重新计算；按goal直接实施授权执行并复验。若未来需要精确的大图拒绝、重采样或全保真导出，须在SDK提供可验证公开契约后另行研究，不承诺当前已经具备。

本记录替代R134-001的编辑就绪/图像失败假设；其PDF缺口、候选、许可、资源边界等未受影响事实继续引用原档案证据，不另做重复选型。

显式外部port的PDFWorker.promise并不确认模块Worker已加载。自有Worker入口仅先导入官方module并发送自有就绪消息，frame在连接SDK之前消费该消息，再交给公开PDFWorker.create(port)。不hook console或上游私有协议；父会话10秒启动期限因此覆盖真实Worker加载。关闭取消监听等待并终止Worker。
